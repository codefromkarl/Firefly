# Local creator system contracts

Applies to `scripts/creator-system.py`, `scripts/creator_system/`, and their interaction with the private Obsidian vault. Canonical architecture and acceptance: [system-design](../../../docs/creator-workflow/system-design.md). Executable usage: [system-operations](../../../docs/creator-workflow/system-operations.md). Do not duplicate those checklists here.

User entrypoints are controlled `creator:system preview` and `scripts/creator-media.py`; the internal renderer is `scripts/creator_system/bilibili-render.mjs`; their contract and acceptance are in [media-delivery-design](../../../docs/creator-workflow/media-delivery-design.md), with usage in [media-delivery](../../../docs/creator-workflow/media-delivery.md). Own recording only; never substitute TTS or test audio for a real narrator. Exact source/cover pairing, input revision identity, private metadata stripping, output preservation, measured audio duration and explicit timing confirmation are delivery contracts. Estimated previews and local clipboard tests cannot imply platform acceptance. Native document outlines and explicitly supplied knowledge relationships must remain distinguishable.

- Keep private sources, state, evidence and exports out of `src/`, `public/`, and tracked content. Project-local vaults belong under ignored `.local/`; original user notes remain user-owned.
- Store returns `{kind,id,revision,digest,data}`. Updates require the expected digest; source versions, evidence, reviews, decisions and receipts are immutable. History and blobs are checked against hashes. SQLite is local state, not a new service or public website collection.
- A replayable source quote is not semantic truth. Preserve parser version, exact locator, source byte identity, capture scope and uncertainty. Only explicit source registration creates a source version; indexing a legacy label never creates proof of review.
- Search defaults to active, non-withdrawn sources. Historical search must preserve freshness information. New network probes are explicit, bounded, public-target checks and do not certify source text or run page instructions.
- Project-owned objects cannot move between projects or enter another project's snapshots. Shared source/evidence references remain explicit. Run cache reuse includes consistent inputs, parameters, tools and model identity.
- Review validity traverses source → evidence → claim → draft → release. A late negative review blocks current delivery; resolution must name the superseded review, and the earlier author decision does not automatically revive. Human identity is locally attested, not cryptographically authenticated.
- Preview reads the captured draft version. A prepared package must match both the draft and exporter hashes. Platform request/result records are not actual provider execution or platform verification; unknown outcomes require reconciliation.
- Controlled preview and new releases only accept Bilibili. Retired release formats cannot be approved or delivered; history remains readable. Bilibili releases bind the original draft identity, title, body, selected images, upload order and marker, preserving immutable blobs. Changes/missing files in the selected delivery directory stale the release and decision; unselected leftover images are not delivered. Asset reads obey project scope. Source normalization lives in internal `article-source.mjs`; no standalone export package commands remain. See `bilibili_package.py` and `test_bilibili_release.py`; operational contract remains in workflow-controls.md.
- Candidate proposals never replace original notes. Generated dashboard refresh checks its owned content hash; user changes are retained as conflicts.
- Restore only to a new directory and allow archive-only recovery without a surviving original vault. Validate a stable captured archive, every extracted member, referenced blobs, contiguous revision history, current/latest revision equality and dependency references. Missing referenced data cannot be blessed by hashing only the files that happen to exist. Report local recovery drills separately from independent-device backups.
- Source recovery copies verified snapshot bytes into a new private file, never a writable alias of its blob. It must preserve the source's active version and withdrawal state, and must not replace existing user files or fabricate new review decisions.

Semantic segmentation and reverse editorial review: canonical scope and acceptance are in [semantic-review](../../../docs/creator-workflow/semantic-review.md); data contracts are in [semantic-contract](../../../docs/creator-workflow/semantic-contract.md).

- Deterministic layout blocks are not semantic analysis. Prepared packets are handoffs; AI-supplied analysis and review remain candidates. Provided source notes do not establish primary-source verification.
- Bind analysis to the document and complete packet hashes, and bind review to the analysis hash. Validate literal review anchors, explicit body coverage/exclusions and nonempty finding segment references. Validation never implies semantic truth or author approval.
- Compile each assigned narration block exactly once and in manuscript order. Preserve semantic segment, source block and narration block IDs through storyboard and frame output. Cache identity includes generated file hashes; do not overwrite existing output packages.
- Revision comparison distinguishes changed body, context, source and ambiguous repeated blocks. Context/source changes may require visual review without automatically requiring new narration. Rerecord hints do not replace comparing edited narration configurations.
- Candidate reports are private editorial artifacts; they do not automatically register workflow reviews, resolve objections or authorize publication.

Validation: `pnpm creator:system-test` includes parser, store, workflow, network-probe mocks, recovery and real CLI/Node-exporter integration. Maintain regression cases for stale review, cross-project misuse, altered tool/model cache inputs, late objections, unknown delivery and backup corruption. Reuse passing website build evidence when its inputs are unchanged; source changes still follow existing frontend gates.

Editorial bridge: `editorial.py` imports scoped, current packet/analysis/review as individual pending reviews with unique literal paragraph anchors and immutable attachments. Context changes cannot silently dismiss an open finding on the same target revision. `draft-impact` produces mapping candidates, never reuses review approval. Preview selection is CAS-managed outside project contracts, and dashboard links derive from selection; failed/stale exports do not silently select a new package. Audit includes preview artifacts and review attachments. Regression owner: `test_editorial.py`.

Revision cycle: new drafts capture a same-project parent and its unresolved reviews, retaining objections without inheriting old validity or approval. An explicit current-draft recheck may supersede inherited IDs; unrelated/other-branch passes may not. review_action records revise/retain/defer intent with scoped candidate snapshots, consecutive idempotency and immutable history; it never resolves or approves. Dashboard labels inherited coordinates as old-draft coordinates and only shows actions for the current draft. Regression owner: test_review_cycle.py.
