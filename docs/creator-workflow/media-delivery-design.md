# 专栏与自录旁白视频交付工程

用户授权：建设内容处理之外的交付工程，使用本人录音；画面包含对应书籍封面、引用文字及问题知识导图。沿用当前任务，避免另建平行内容研究。本文是本阶段唯一验收清单。

## 工程边界

- 输入是已有 Markdown、明确选择的书籍引用/导图配置，以及本地自录音频；不新增观点、不伪造书中引文、不调用 TTS。
- 专栏采用保守富文本子集并输出图片上传清单；当前公开编辑器入口为 https://member.bilibili.com/york/read-editor 。平台保留哪些粘贴样式需实际编辑器预览；本地成功不能写成平台已验收。
- 输出包括独立标题、富文本复制页面、纯文本备用稿、配图及顺序；复制动作不自动上传本地图片，插图以明确占位提示人工上传。
- 视频默认 1920×1080、30fps、MP4/H.264/yuv420p/AAC，属于本项目工程默认，不声称是平台唯一格式或官方上限。录音保持原时间线，不自动裁切变速。
- 一条完整录音配显式连续 cue；若没有 cue，只生成估算预览并标记待确认。缺录音仍可完成分镜及图片，但不称已合成本人旁白视频。
- 只读使用本地书封面并记录来源，保持比例。直接引文必须来自明确的书单摘录索引或已登记证据；人工附加文本标明转述/待核查，不能给它自动加引号冒充原句。
- 自动导图只表达文稿标题/结构关系；因果、支持、反驳等关系必须由显式图配置提供，导出不自行发明。

## 数据与接口

`creator-media.py plan` 将已有文稿提取为可编辑分镜JSON；章节与原段落保留。视觉补充JSON可以选择书目引用卡或提供显式导图数据。图片renderer只读plan，生成PNG、frames.json、图片清单与浏览预览；合成器读取frames.json和本人录音。

frames.json统一字段：`schema=1,title,width,height,fps,timing_confirmed,audio.path,demo_audio,scenes[]`。scene包含 `id,image,narration,start,end,source_refs`；image相对frames.json。没有时间字段时只能按文字长度估时预览。部分缺时、重叠、空隙、超出音频、NaN均需报告。

书籍来源复用 Firefly 的稳定slug和cover文件。文稿、分镜、封面、图配置、音频和每个输出都记录哈希。不同输入不能覆盖旧输出或用户修改文件；重建使用新目录。

专栏assets.json：`{schema:1,images:[{id,path,caption,after_heading?,source?}]}`，路径相对manifest，资源显式选择。私有路径仅在本地内部构建记录出现，公开稿、图中文字和图片上传清单不暴露原目录。

## 视觉约定

- 色彩：纸白 #F7F9FC、文字深蓝 #16324F、重点蓝 #295CCB、辅助绿 #2F7768、细线灰 #D8E0EC。
- 字体：本机 Noto CJK，中文标题与正文清晰分级；避免长篇文字压成小字号。
- 引用卡：左侧保持比例的书封面，右侧引用及明确出处；没有有效封面时报告问题，不生成假封面。
- 导图：中心问题与少量分支；必要时拆成总览与逐分支图。图中区分结构顺序与显式论证关系。
- 正文卡：一个主题、一段或少量条目。超长文字拆页或拒绝溢出，不悄悄截断。
- 使用程序排版确保文字精确；不需要图片生成模型绘制文字或伪造书封面。

## 责任分工

- root：分镜计划、图片/导图renderer、统一CLI、集成、实际视觉与音视频检查。
- editorial_pipeline：独立B站专栏导出器、测试及使用说明。
- obsidian_bridge：FFmpeg合成、时间轴、字幕、缓存保护及测试。
