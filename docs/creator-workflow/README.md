# 从书单到 Obsidian，再到 B 站专栏

录音前可使用 [语义分段与分镜反向审稿](semantic-review.md)：明确每段的问题与论证、生成画面计划、定位文稿薄弱环节，并追踪修订影响。

日常专栏统一为：项目与来源 → 证据/观点 → 登记稿件 → 审查 → `creator:system preview` 生成 B 站图文包 → `release-prepare` 固定版本 → 作者决定 → 平台人工预览与发布 → 回填。命令见下文及 [系统操作](system-operations.md)。

文字专栏独立完成。需要视频时才使用 [媒体交付操作](media-delivery.md) 生成分镜并接入本人录音；视频和录音不是专栏的前置条件。

系统合同以 [流程、职责与控制设计](system-design.md) 为准；本地版本、证据、任务、审查与交付工具已实现，日常入口见 [系统操作与控制验收](system-operations.md)。Obsidian 中打开“系统首页”。本页保留最初的笔记与导出操作，不把历史内容自动升级为已审阅材料。

本目录提供可执行的首期示范：问题 → 书单材料 → 联网查证和反例 → 独立观点 → 主稿 → 公开格式导出 → 人工平台预览与发布 → 反馈回流。实际接入设备、仓库路径及命令见 [Obsidian 接入说明](obsidian-integration.md)。

这是一套本地文件工作流。导入和导出脚本不会自行联网研究，不会后台监控 Obsidian，也不会登录或发布到 B 站。联网研究由当前助手按作者选题执行，把核查结果写回来源与研究笔记；之后作者审阅观点和稿件。

## 每期如何实际执行

| 环节 | 输入 → 输出 | 工具与操作 | 完成依据 |
| --- | --- | --- | --- |
| 收集问题 | 读者困惑 → 收件箱 | Obsidian 普通笔记或浏览器手动保存 | 问题包含对象与困惑 |
| 确定主线 | 宽主题 → 主题研究、项目卡 | Properties、双链、书单索引 | 一期只有一个明确主问题，限定不讲什么 |
| 带问题读书 | 书籍 → 有定位的来源笔记 | EPUB/PDF 阅读器；扫描书才考虑 OCR | 保留版本、章节/位置；文本核对与作者认同分开 |
| 网络研究 | 主张与疑点 → 来源、反例、候选书 | 当前助手 web 搜索或浏览器，优先作者、机构、论文原页 | 打开原文；记录支持、反驳或边界，来源类型与实际阅读范围 |
| 提炼观点 | 多份材料 → 独立知识卡片 | Obsidian 链接、反向链接、属性 | 写清原话/作者观点/研究结果/自己的推断，不隐藏冲突 |
| 形成论证 | 观点 → 提纲与证据对应 | 主题笔记、项目研究账本 | 每个主要结论有依据和适用条件；候选书不充当已读证据 |
| 写作与审阅 | 提纲 → 主稿 | 作者与当前助手协作；朗读检查 | 核心判断可追溯；个人案例真实；AI草稿待作者确认 |
| 排版导出 | 登记稿件 → B 站图文包 | creator:system preview；标题、正文、图片顺序一起检查 | 来源仍在、私有元数据不在；明确仅本地预览 |
| 平台交付 | 导出稿 → 平台草稿 → 发布 | B 站当前编辑器人工粘贴、设标题/封面/引用 | 记录平台预览；作者执行发布并回填链接 |
| 复盘迭代 | 反馈 → 问题、修订、下期 | 发布与复盘笔记；第7天/第30天人工回收 | 错误回到来源与观点；记录真实数据，不只追求阅读量 |

## 对当前助手的协作指令

在 Obsidian 内写好项目卡，然后把项目卡路径或必要内容交给当前助手。例如：

> 请读取本地仓库的 `40 内容项目/001 财富自由/项目卡.md` 和所链接的来源、观点。先检查现有证据，再联网查找一个可能推翻核心主张的原始来源。把查询、原文定位、核查范围和“支持/反驳/边界”写入研究账本；来源不足就收窄观点。书单外资料只建候选，不标已读。更新主稿，运行校验与导出，保留人工审阅和发布记录。

这是显式启动一次协作。仅在库中编辑模板不会自动触发模型或联网。未来若需要桌面自动触发、API Key、付费检索或第三方插件，作为单独需求选择；首期不需要安装这些工具。

## 书单外材料如何进入系统

1. 从具体缺口出发，例如“知足是否意味着超过某收入后钱就无效”。写出可被反驳的主张。
2. 先搜原始研究、作者官方材料、机构方法说明。搜索摘要用于发现，打开原文后才记录 text_checked；只看书籍介绍则 metadata_only。
3. 判断是否回答同一问题。概念不同不算直接反驳，别把财务福祉当成财务独立。
4. 对研究记下样本、测量对象、关联/因果与适用边界。需要数字时核对表格、单位和年份；无法核实就不用。
5. 对新增书籍核对书名/作者/版本，去重现有书单及本地文件。建 source_type: book_candidate、reading_status: unread，写“要解决的缺口”和待阅读章节。
6. 获得合法正文并实际读取相关部分后，建立可定位的来源记录；是否读完全书另记，不能把一次检索自动改成已读。
7. 新来源改变结论时，同时修改观点、稿件及已发布内容的纠错记录。来源数量不作为质量目标。

首期示范包括：PNAS 原始研究限制“所有人的幸福都在同一收入封顶”的泛化；Four Thousand Weeks 是时间取舍问题的候选，仅核对作者官网介绍，未读、未购，未用于本期论证。具体查询和采用/排除理由都保存在 `研究与证据.md`。

## 笔记契约

- `source`：稳定 `id`、`source_type`、`url` 或 `locator`、`verification`、`accessed`；关联书单时用 `book_id`。`text_checked` 仅指相关文本已核对，`metadata_only` 指只核实元数据，`pending` 指待核查。
- `claim`：`id`、`claim_type`、`sources`、`topics`、`verification`。本期统一 `pending_review`，不能用脚本运行成功自动改成人工认可。
- `topic / project / article`：稳定 `id`、状态与有关链接。主稿 frontmatter 可以含内部双链，但正文必须可独立公开。
- 列表属性使用扁平 YAML 数组；双链按 `[[目录/笔记]]` 或 `[[目录/笔记|显示名]]`。来源定位不写在主稿正文。
- 原始书籍导入保留阅读状态和 AI 预读属性，不因稿件引用自动提升整本书状态。书籍由导入器管理，创作笔记由作者管理。

## 统一专栏入口

首次按 [系统操作](system-operations.md) 建立项目、登记来源/证据、观点和稿件。已有旧稿可以先登记待审候选；尚未完成的证据映射必须保留为审查异议，不把空映射解释为事实已核对。

```bash
pnpm creator:system --vault '.local/creator-vault' preview \
  --draft DRAFT-ID --assets '.creator-system/assets/PROJECT-v1/assets.json'
pnpm creator:system --vault '.local/creator-vault' release-prepare --spec /path/to/release.json
```

`--assets` 无图时省略；路径相对 vault，素材及 manifest 都必须处于项目可读范围。默认按稿件版本、格式和素材版本选择输出目录；也可用 `--output` 指定新的 vault-relative 版本目录。成功预览会登记产物版本并更新项目当前选择，自动刷新系统首页；项目卡链接系统首页，不再人工维护一份目录状态。更新稿件/素材时采用新目录；清理旧版本需明确指定范围，不靠目录名称推断已批准。

打开其中的 `bilibili.html`，分别复制标题和正文，按 `asset-order.json` 上传 `images/` 中当前列出的图片。`bilibili.txt` 是纯文本备用稿。可用 `review-action` 记录修订、保留或暂缓及理由；新稿会保留前一稿未解决意见。至少一份当前稿件 pass 审查且无未解决异议，才能 prepare release；作者决定再绑定最终标题、正文和图片清单的精确版本。平台操作步骤见 [B 站交付](bilibili-export.md)。

专栏日常命令只使用上述受控入口；内部适配器供系统及媒体构建复用，不再提供独立的 package 命令。

## 首次导入

在 Firefly 根目录执行。首次导入及重复导入先检查计划；出现冲突时保留用户笔记，按接入说明处理。本机日常导出以实际仓库稿件为输入，`example-vault` 只是初始模板，不会自动跟随个人修改：

```bash
pnpm creator:import --vault '.local/creator-vault' --seed 'docs/creator-workflow/example-vault'
pnpm creator:validate --vault '.local/creator-vault'
```

导入计划确认无冲突后，在第一条命令末尾加 `--apply` 执行。已写过的笔记不需要每期重新导入。`creator:validate` 检查 ID 与链接完整性，并报告未审阅状态；它不替代事实核查，也不是自动发布门禁。

导出器拒绝未处理的内部双链、Obsidian 注释、本地文件路径、非 HTTPS 引用、原始 HTML和图片嵌入，避免将私人资料或主动内容随正文发送。图片在平台编辑器人工上传并记录授权；本工具不判断整篇稿件是否值得公开，内容审阅仍需作者完成。

HTML 的排版是本地预览，不能证明 B 站会保留全部样式。实际粘贴后检查标题、段落、引文和每个来源链接。平台不保留超链接时使用纯文本完整网址。没有经过编辑器检查和实际发布，就保持 unpublished。

## 工具选择与当前证据

| 类别 | 工具 | 当前边界 |
| --- | --- | --- |
| 已执行 | 本地 EPUB 定位读取、web 原始资料查询、Markdown/HTML 导出测试 | 本轮可审查来源与脚本；不是全自动研究系统 |
| 原生可用 | Obsidian 内部链接、反向链接、Properties、Templates、Bases | 无需社区插件；实际启用情况以本机仓库为准 |
| 首期人工操作 | 浏览器复制富文本、B 站编辑器、发布后反馈回收 | 未把平台兼容或发布状态当作已完成 |
| 按需选择 | Zotero / 浏览器剪藏 | 文献多时用于管理；首期来源笔记已足够 |
| 按需选择 | OCR | 仅扫描材料需要，OCR结果仍需对照原图 |
| 按需选择 | 图表工具、图片生成、音视频录制剪辑 | 取决于作品表达，不强制购买、安装或生成素材 |

下一步优先用真实 Obsidian 笔记完成一轮人工内容审阅、导出、平台粘贴预览，再决定自动化最耗时的环节。同步、备份和版本冲突以接入说明为准。
